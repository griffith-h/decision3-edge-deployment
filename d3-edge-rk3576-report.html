优化了什么，为什么保留 3 线程

78 个文本线性层继续使用 RKNN FP16 矩阵乘。CPU 侧采用自己编写的 ARM64 RMSNorm / 四抽头因果卷积融合算子、128 扫描分块、仅文本的 FP32 SDPA；保持 BF16 舍入边界和不支持路径的回退。原始 12 层、权重、非因果完整注意力、因果 GatedDeltaNet、视觉塔与输出 readout 均保留。无需厂家执行器源码或逆向。

4–7 四个 A72 核可用，但 Torch 计算线程和 OpenMP 上限均设为 3。4 线程融合版独立模型测试中位数 0.824 秒、最慢 1.397 秒，98/100<1 秒；3 线程的中位数略高但本轮尾延迟更稳定。原服务 Python 健康探针每次消耗约 0.9–1.0 秒 CPU，曾与慢峰重叠；新容器改为每 30 秒 curl 探针。没有关闭探针、改变系统 governor 或使用请求结果缓存。

"""Production entry point for the validated three-thread RKNN hybrid release."""
import argparse
from concurrent.futures import Future
import json
import os
from pathlib import Path
import queue
import signal
import sys
import threading
import torch

RELEASE = '2026-10-17-three-thread-v1'

def main():
    parser = argparse.ArgumentParser()
    parser.add_argument('--model', required=True)
    parser.add_argument('--port', type=int, default=8900)
    args = parser.parse_args()
    sys.path[:0] = ['/base', args.model]
    from cpu_optimized_server import optimize
    from rknn_linear import Engine, install, uninstall
    from cpu_attention_optimized import install_conv, install_scan, install_sdpa
    from native_norm import install_norm, install_native_conv
    from d3_runtime import D3, PromptEncoder
    from d3_server import serve
    assert os.environ.get('OMP_THREAD_LIMIT') == '3'
    assert os.environ.get('OMP_NUM_THREADS') == '3'
    torch.set_num_threads(3)
    model = D3.from_pretrained(args.model, device='cpu', verify='full')
    model.model_name = 'vllm-sr/d3-edge'
    assert model.attention_mode == 'noncausal_full_attention'
    assert isinstance(model.encoder, PromptEncoder) and len(model.encoder.stack) == 12
    optimize(model)
    engine = Engine()
    restore, stats = [], {}
    server, http_thread = None, None
    pending = queue.Queue()
    stopping = threading.Event()
    admission = threading.Lock()
    def stop(signum, frame):
        stopping.set()
        pending.put(None)
    signal.signal(signal.SIGTERM, stop)
    signal.signal(signal.SIGINT, stop)
    try:
        selected = install(model, engine)
        assert len(selected) == 78
        restore.extend([install_conv(), install_scan(128), install_sdpa(),
                        install_norm(model.backbone, stats), install_native_conv(stats)])
        body = json.loads(Path('/base/request.json').read_text())
        model.system_one(state=body['state'], questions=body['questions'])
        assert stats.get('norm_calls', 0) > 0 and stats.get('conv_calls', 0) > 0
        if stopping.is_set():
            return
        server = serve(model, '0.0.0.0', args.port,
                       api_key=os.environ.get('DECISION_API_KEY') or None)
        original_answer, original_health = server.decider.answer, server.decider.health
        def health(authentication):
            result = original_health(authentication)
            result['deployment'] = {'release': RELEASE, 'torch_threads': torch.get_num_threads(),
                'OMP_THREAD_LIMIT': os.environ['OMP_THREAD_LIMIT'],
                'affinity': sorted(os.sched_getaffinity(0)), 'chunk_size': 128,
                'rknn_linear_layers': len(selected), 'native_stats': dict(stats)}
            return result
        def queued_answer(body):
            future = Future()
            with admission:
                if stopping.is_set():
                    raise RuntimeError('Service is stopping')
                pending.put((body, future))
            return future.result()
        server.decider.answer, server.decider.health = queued_answer, health
        http_thread = threading.Thread(target=server.serve_forever, name='d3-http', daemon=True)
        http_thread.start()
        print('SERVICE_READY', json.dumps(health(False)), flush=True)
        while not stopping.is_set():
            item = pending.get()
            if item is None:
                break
            body, future = item
            try:
                future.set_result(original_answer(body))
            except Exception as exc:
                future.set_exception(exc)
    finally:
        stopping.set()
        with admission:
            while not pending.empty():
                item = pending.get_nowait()
                if item is not None:
                    item[1].set_exception(RuntimeError('Service is stopping'))
        if server is not None:
            if http_thread is not None:
                server.shutdown()
            server.server_close()
        for callback in reversed(restore):
            callback()
        uninstall(model)
        engine.close()
        print('SERVICE_STOPPED_CLEANLY', flush=True)

if __name__ == '__main__':
    main()

1. 固定版本和输入

在 192.168.1.164 的 root shell 中执行后续板端命令。依赖为 Docker、g++、Python 3、可访问的 /dev/dri 和现有镜像 decision3-edge:arm64-cpu。镜像原测试 ID 为 sha256:cd5c294eb741dd011ad31f8dbc6ab10a088123922122f06d2c29b7d89067d49d；Torch 2.12.0+cpu、Transformers 5.17.0，CPU 核心 4–7、4 个 Torch 线程、8 GiB 容器内存。

模型固定为 vllm-sr/d3-edge@20c745653400d191ecacd99c4eafc0c5900dc15e，使用官方 12 层权重；每次模型加载执行完整文件哈希验证。缓存位于 /root/.local/state/vllm-sr/engine/vllm-sr--d3-edge/models/model-runtime，需保留其 models--vllm-sr--d3-edge/snapshots/版本号 层级。板端源码在 /opt/decision3-edge-matmul，SDK 固定提交 2c723177a94fac65cbc036d722907ddbc91980cf，Runtime 2.5.0、驱动 0.9.8。脚本对 SDK 文件按 sdk-manifest.json 校验 SHA256。

复现所需文件包括 matmul_bridge.cpp、rknn_linear.py、cpu_optimized_server.py、benchmark.py、micro_test.py、boundary_test.py、request-cases.json、golden-reference.json 和 sdk/。它们已保存在板端和本机项目的 rknn-matmul-experiment/；重建镜像使用项目根目录的 Dockerfile 与 Dockerfile.server，依次构建标签 decision3-edge-rk3576:torch2.12 和 decision3-edge:arm64-cpu。

2. 运行完整模型与矩阵测试

下面的复现脚本会暂时停止当前运行的 CPU / RKNN 服务以避免争用，在独立目录编译桥接库，依次执行矩阵测试、边界测试和 5 个完整模型用例。退出时尝试恢复原先运行的容器，原先停止的容器保持停止；启动完成后仍应检查健康接口。此脚本本轮已做 bash -n 语法检查，未重新执行整套性能测试。

bash /opt/decision3-edge-matmul/reproduce-rknn.sh

每个模型用例先预热，再对 CPU 和 RKNN 各计时 3 次取中位数；不计模型加载、NPU 权重缓存建立及 HTTP 时间。提速 = CPU 中位数 ÷ RKNN 中位数；对同一输出路径的概率 / score 取最大绝对差，排除 confidence、legend。通过标准：选项一致且最大差 ≤ 0.01。输入以固定的 request-cases.json 和 golden-reference.json 为准，不临时替换样本。

新结果位于 /opt/decision3-edge-matmul/reproduction-时间-随机串/logs/，包括 benchmark-all.json、micro-test.json、boundary-test.json 及控制台日志；主脚本最后打印目录、耗时、倍数、最大差和选项一致性。原始 /opt/decision3-edge-matmul/logs/ 不覆盖。新测值受温度、后台负载及运行波动影响，不保证与报告逐位一致。

展开完整复现脚本（HTML 内置）
#!/usr/bin/env bash
# Run on the RK3576 board as root. Uses a separate directory for all new logs.
set -euo pipefail
source_dir=/opt/decision3-edge-matmul
model_cache=/root/.local/state/vllm-sr/engine/vllm-sr--d3-edge/models/model-runtime
model_path=/models/models--vllm-sr--d3-edge/snapshots/20c745653400d191ecacd99c4eafc0c5900dc15e
run_dir=$(mktemp -d "$source_dir/reproduction-$(date +%Y%m%d-%H%M%S)-XXXXXX")
mkdir "$run_dir/logs"
for file in benchmark.py micro_test.py boundary_test.py cpu_optimized_server.py rknn_linear.py matmul_bridge.cpp request-cases.json golden-reference.json sdk-manifest.json; do
  cp "$source_dir/$file" "$run_dir/$file"
done
cp -a "$source_dir/sdk" "$run_dir/sdk"
python3 - "$run_dir" <<'PY'
import hashlib, json, pathlib, sys
root = pathlib.Path(sys.argv[1])
manifest = json.loads((root / 'sdk-manifest.json').read_text())
for name, expected in manifest['files'].items():
    actual = hashlib.sha256((root / 'sdk' / name).read_bytes()).hexdigest()
    assert actual == expected['sha256'], f'SDK hash mismatch: {name}'
print('PASS: pinned RKNN SDK file hashes')
PY
restore_containers=()
restore_services() {
  for container in "${restore_containers[@]}"; do
    docker start "$container" || printf 'Failed to restore %s\n' "$container" >&2
  done
}
trap restore_services EXIT
for container in decision3-edge decision3-edge-matmul; do
  if [[ $(docker inspect --format '{{.State.Running}}' "$container" 2>/dev/null || true) == true ]]; then
    restore_containers+=("$container")
    docker stop "$container"
  fi
done
cd "$run_dir"
g++ -O2 -std=c++17 -shared -fPIC -I sdk matmul_bridge.cpp -L sdk -lrknnrt \
  -Wl,-rpath,'$ORIGIN/sdk' -o libmatmul_bridge.so
run_check() {
  docker run --rm --cpuset-cpus 4-7 --memory 8g --memory-swap 8g --device /dev/dri \
    --mount "type=bind,source=$model_cache,target=/models,readonly" \
    --mount "type=bind,source=$run_dir,target=/work" \
    --workdir /work decision3-edge:arm64-cpu "/work/$1" "${@:2}"
}
run_check micro_test.py 2>&1 | tee logs/micro-test.log
run_check boundary_test.py 2>&1 | tee logs/boundary-test.log
run_check benchmark.py --model "$model_path" --selection all --repeats 3 2>&1 | tee logs/benchmark-all.log
python3 - "$run_dir/logs/benchmark-all.json" <<'PY'
import json, sys
report = json.load(open(sys.argv[1]))
assert report['passed']
for name, case in report['cases'].items():
    result = case['npu']
    print(f"{name}: CPU={case['cpu']['median_seconds']:.3f}s RKNN={result['median_seconds']:.3f}s "
          f"speedup={result['speedup']:.2f}x max_delta={result['max_probability_or_score_delta']:.8f} "
          f"same_choice={result['choices_unchanged']}")
PY
printf 'PASS; new evidence directory: %s/logs\n' "$run_dir"

局域网调用示例

这是分类 / 评分接口。示例判断输入属于编程、数学还是聊天，并不生成 Python 函数正文。

API / 8900

健康检查：http://192.168.1.164:8900/health；推理接口：POST /v1/systemone。

curl --max-time 120 'http://192.168.1.164:8900/v1/systemone' \
  -H 'Content-Type: application/json' \
  --data-binary @- <<'JSON'
{
  "model": "vllm-sr/d3-edge",
  "state": "请写一个 Python 函数，合并两个有序列表。",
  "questions": {
    "kind": {
      "type": "choice",
      "instructions": "这个请求属于哪类任务？",
      "criteria": {
        "code": "编程任务",
        "math": "数学问题",
        "chat": "日常聊天"
      }
    }
  }
}
JSON

返回 answers.kind.choice 及各选项概率；本例预期选择 code。请求串行执行，超过原生矩阵支持范围时保留 CPU 回退路径。
